# Mission 0 — Create your GitHub workspace

## 1. Task / objective
Set up a correctly named GitHub repository with the required folder structure for all missions, and prepare a root README.

## 2. Work completed
- Decided on the repository name following the naming rule: `digital-detective-XXXX` (assignment name + last four USN digits).
- Created the local project folder with the exact repository name.
- Created all nine mission folders (`mission-00-setup` through `mission-08-final-report`), each containing a `README.md`.
- Created the `evidence/` folder for optional screenshots and outputs.
- Prepared the root `README.md` with project title, mission index, and navigation links.
- Published the repository to GitHub as a public repository.

## 3. Commands / tools used
- `mkdir -p` — Created the project directory and all mission subdirectories in one step.
- `touch` — Created empty README.md files inside each mission folder.
- `git init` — Initialised the local folder as a Git repository.
- `git add .` — Staged all newly created files.
- `git commit -m "Set up Digital Detective mission structure"` — Saved the initial snapshot.
- `git remote add origin <URL>` — Connected the local repository to the GitHub remote.
- `git push -u origin main` — Published the initial commit to GitHub.

## 4. My understanding
A repository is a project folder tracked by Git. Organising it by mission keeps each topic separate, makes navigation easy, and ensures each mission can be committed and reviewed independently. The folder structure acts like a table of contents for the entire assignment.

No major difficulties. The setup was straightforward once the naming convention and folder layout were clear from the assignment instructions.
